# 吉时已到 功能 Demo

## Vercel 发布

已提供 `api/[...path].js` 服务端函数与 `vercel.json`，可从 GitHub 导入本仓库。构建命令 `npm run build`，输出目录 `dist`，使用 Node.js 22.12 或更新的受支持版本。

在 Vercel 项目的 Environment Variables 中设置 `.env.example` 列出的六项配置，作用于 Production 和需要的 Preview 环境，再重新部署。不要使用 `VITE_` 前缀，密钥不提交到 Git。云端函数沿用本地 `/api/*` 协议。

此版本是演示应用，闹钟与用户偏好保存在当前浏览器，页面关闭后不运行闹钟与晚间通知。云端环境下各供应商的网络连通性应以部署后的真实检查为准。

## 今天的主线演示

1. 点击“10 秒后响铃演示”，保持页面打开，验证响铃、停止与稍后提醒。
2. 点击“获取真实天气与驾车路线”，默认使用上海两点示例，或输入 WGS84 经纬度。
3. 设定未来到达时间、准备与缓冲时间，点击“根据真实数据计算闹铃”。
4. 查看出发时段预报与调整理由，应用方案；刷新页面验证闹铃恢复。刷新后请点“启用声音 / 试听”以重新取得浏览器声音授权。

天气来源 Open-Meteo，路线来源 OSRM / OpenStreetMap。无需密钥，适合非商业 Demo；不保证公共服务持续可用。坐标仅在点击查询时发送给服务商，页面不自动定位。驾车距离与基础耗时来自真实路线，**不含实时拥堵或明早路况预测**。坐标应为 WGS84，不可直接混用高德 GCJ-02。暂不提供精确地址搜索、公交或骑行真实算路。

天气取家附近出发时段的逐小时预报，不代表完整路线上所有位置；雨雪预留是用户设置的准备时间，不是预测的堵车时长。数据超过 15 分钟需要重新查询。页面支持手动更新，暂无后台轮询。计算并确认后才写入网页闹铃，超限需明确确认，不延后已有更早闹铃。

网页响铃依赖 AudioContext、用户声音授权和页面计时器。关闭页面不会响铃；后台节流、休眠、系统静音可能导致延迟或无声音。超过一分钟的过期任务会标记错过而非宣称准时触发。不能替代原生系统闹钟。

## 启动

需要 Node.js 22.12+（或兼容当前 Vite 的更新版本）。在项目目录运行：

```powershell
npm install
npm run dev
```

打开终端显示的本地地址，默认 http://127.0.0.1:5173 。

```powershell
npm test
npm run build
```

## 备用模拟演示

1. 展开“备用演示”，保持默认参数，选择晴天，生成方案：07:40 起床。
2. 切换降雨，生成方案：07:20 起床，08:05 出门，08:50 到达。
3. 模拟执行，查看记录；刷新页面验证保存；点击撤销。
4. 切换降雪：提前 40 分钟，超过默认 30 分钟授权，必须确认本次执行。
5. 选择数据不可用，或关闭模拟授权：不执行闹钟调整。

## 备用模拟区边界

- 备用区域的天气和路线为演示数据，独立于上方真实数据功能；未接入大模型 API。
- 模拟执行只写入浏览器 localStorage，不设置系统闹钟，不会响铃。浏览器关闭后没有后台任务。
- 不包含工作日调度、日期/节假日、冻结时间、晨间动态更新、登录或云端存储。
- 反馈只记录，不自动训练或调整策略。记录最多 50 条，清理浏览器数据会丢失。
- 本地可运行 Demo 不代表已达到手机闹钟产品的可靠性要求。
